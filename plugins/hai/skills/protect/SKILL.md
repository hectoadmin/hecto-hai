# 보호 폴더를 운영체제 수준에서 막기

가드 훅은 명령 글자를 보고 막는 안전망이다. 샌드박스는 운영체제(macOS Seatbelt·Linux)가 Bash 의 파일 읽기 자체를 막으므로 명령을 어떻게 써도 통과하지 못한다. 플러그인은 이 설정을 스스로 바꿀 수 없어서, 사용자 동의를 받아 사용자 설정 파일에 넣는다.

## 순서
1. `hai_status` 를 불러 보호 폴더·원문 결과 폴더와 현재 샌드박스 상태를 확인한다. Windows(WSL 아님)면 "Windows 에서는 샌드박스가 없어 가드 훅만 동작합니다" 라고 알리고 끝낸다.
2. 사용자 설정 `~/.claude/settings.json` 을 읽는다(없으면 새로 만든다). 다른 설정은 건드리지 않는다.
3. 바꿀 내용을 **그대로 보여 주고** 동의를 받는다:
   ```json
   {
     "sandbox": {
       "enabled": true,
       "filesystem": { "denyRead": ["<보호 폴더들>", "<원문 결과 폴더>"] }
     }
   }
   ```
   - 이미 있는 `sandbox` 설정이 있으면 `denyRead` 에 빠진 경로만 더한다(지우지 않는다).
   - 함께 알릴 것(짧게): 샌드박스를 켜면 Claude 가 실행하는 명령은 **작업 폴더와 임시 폴더에만 쓸 수 있고**, 처음 쓰는 인터넷 주소는 허락을 묻는다. 막히는 작업이 생기면 Claude 가 "샌드박스 밖에서 실행"을 물어본다 — 그때 원문 폴더를 읽는 명령이면 거절하면 된다.
   - 더 엄격하게(샌드박스 밖 실행을 아예 못 하게) 하려면 `"allowUnsandboxedCommands": false` 도 넣을 수 있다고 한 줄 덧붙인다. 기본으로는 넣지 않는다.
4. 사용자가 "예" 라고 하면 그때만 파일을 고친다(JSON 형식이 깨지지 않게 읽고-합치고-쓰기). 아니면 아무것도 바꾸지 않는다.
5. "Claude Code 를 다시 시작하면 적용됩니다. 다시 시작한 뒤 /hai:guide 나 hai_status 로 '읽기 차단됨' 이 나오는지 보세요." 로 끝낸다.

## 하지 않는 것
- 사용자 동의 없이 설정을 바꾸지 않는다. 프로젝트 설정(`.claude/settings.json`)이 아니라 사용자 설정에 넣는다(모든 작업 폴더에 적용되게).
- `denyRead` 에 홈 폴더 전체(`~`)처럼 넓은 경로를 넣지 않는다 — 평소 작업이 막힌다.
