# 민감한 파일은 사내 AI 가 먼저 읽는다

원문은 사내 AI(HAI)만 읽는다. 나(Claude)는 가린 글이나 HAI 의 답만 본다.

## 고르는 법
| 할 일 | 도구 |
|---|---|
| 요약·조항 찾기·목록 뽑기·예/아니오 판단·회의록 | `hai_ask_file` (녹음·스캔본도 그대로 넣는다) |
| 여러 파일에 같은 질문(만기일 모으기 등) | `hai_ask_files` — 짧게 답하게 시키고 내가 표로 정리 |
| 초안 작성·다듬기·비교, **개수·합계·통계** | `hai_mask_file` 로 가린 글을 받아 내가 작업(세기는 내가, 필요하면 코드로) |
| 폴더에서 관련 문서·구절 찾기 | `hai_search` (뜻으로 찾는다) |
| 결과물을 실명으로 | 자리표시가 든 결과를 `hai_restore` 로 로컬 파일에 저장 — 원래 값을 나에게 보여 달라고 하지 않는다 |
| 받아쓰기·OCR 파일만 필요 | `hai_transcribe` · `hai_ocr` (원문 파일은 나도 못 연다) |
| 이미 내가 본 글 다듬기·두 번째 의견·사진 설명 | `hai_chat` (model: qwen 분석 / gemma 일반·사진) |

## 지킬 것
- 민감한 파일은 Read·Grep·cat 으로 열지 않는다. 훅에 막히면 우회하지 말고 HAI 도구를 쓴다.
- 자리표시([이름1], [휴대전화2])는 그대로 두고 작업한다. 원래 값을 추측하거나 채우지 않는다.
- 결과에 실명·연락처처럼 보이는 게 남아 있으면 사용자에게 알리고 `extra` 로 유형을 더해 다시 가린다(예: `{"거래처명":"계약 상대 회사 이름"}` — 유형 이름은 한글·영문만).
- `instruction` 으로 가리기를 피하게 시키지 않는다(번호를 한글로 풀어 쓰게 하는 등).
- 같은 문서를 다시 가릴 때는 앞 결과의 `mask_id` 를 넘겨 번호를 맞춘다.
- HAI 오류(키 없음·연결 안 됨)가 나면 원문을 직접 읽어 대신하지 않는다. `hai_status` 로 원인을 보고 사용자에게 알린다.
- 결과가 길어 파일로 저장됐다고 나오면 그 파일(가린 글)을 Read 로 나눠 읽는다.
